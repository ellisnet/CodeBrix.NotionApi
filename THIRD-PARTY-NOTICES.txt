CodeBrix.NotionApi is a .NET client library for the Notion API, delivered
as the single CodeBrix.NotionApi assembly in the
CodeBrix.NotionApi.MitLicenseForever NuGet package. The CodeBrix.NotionApi
assembly incorporates third-party source code as described below.

CodeBrix.NotionApi issues HTTP requests to the Notion API
(https://api.notion.com). Use of that service is governed by Notion's own
terms of service; see https://www.notion.com/notion/terms-and-privacy

Jeremy Ellis and contributors license the CodeBrix.NotionApi project
to you under the terms set forth in the LICENSE file, which is located at
the root of this repository.

If you have any questions about any third-party code or services referenced
here, or if you believe that any third-party code has been included in
CodeBrix.NotionApi in error, please open a new issue at:
https://github.com/ellisnet/CodeBrix.NotionApi/issues

   Non-trivial modifications made during the port:
     - All JSON serialization was migrated from Newtonsoft.Json to
       System.Text.Json; the Newtonsoft.Json dependency was removed.
     - The JsonSubTypes dependency was removed; discriminator-based
       polymorphic deserialization is provided by the
       CodeBrix.Json.Extensions.MitLicenseForever NuGet dependency instead.
     - Namespaces were renamed from Notion.Client[.*] to CodeBrix.NotionApi,
       and block-scoped namespaces were converted to file-scoped.
     - [JsonProperty("x")] attributes became [JsonPropertyName("x")];
       [EnumMember(Value = "x")] enum values became
       [JsonStringEnumMemberName("x")]; StringEnumConverter became
       JsonStringEnumConverter; IsoDateTimeConverter attributes were
       dropped (System.Text.Json defaults to ISO 8601); Newtonsoft custom
       converters were rewritten as System.Text.Json converters.
     - [JsonProperty] attributes that upstream declared only on INTERFACE
       members (honored by Newtonsoft as a fallback, ignored by
       System.Text.Json) were propagated onto the implementing classes.
     - Upstream JsonSubTypes fallback declarations that referenced the
       declaring type itself were redirected to new Unknown* subclasses,
       because the System.Text.Json converter cannot dispatch a type to
       itself without recursing.
     - The empty concrete base classes Filter, RichTextBaseInput and
       DataSourcePropertyConfigRequest were made abstract so the
       runtime-type serialization path applies to them. (System.Text.Json
       serializes the DECLARED type and does not inherit a base class's
       [JsonConverter], so leaving them concrete dropped every subtype
       payload they carried.)
     - [JsonConverter(typeof(StringEnumConverter))] attributes that
       upstream placed on STRING-typed properties (tolerated by
       Newtonsoft, rejected by System.Text.Json) were dropped.
     - [EnumMember(Value = null)] enum values were dropped (equivalent to
       the default member-name behavior).
     - The WireMock.Net, FluentAssertions, Moq.AutoMock, and xunit (v2)
       test dependencies were replaced with an in-repo fake
       HttpMessageHandler harness (FakeServer), an in-repo IRestClient
       recording fake (RecordingRestClient), SilverAssertions, and
       xunit.v3; *Test file/class names were renamed to *Tests.
     - The Microsoft.SourceLink.GitHub package reference was dropped.
     - UpdateCommentRequest.CommentId and UpdateViewRequest.ViewId are
       [JsonIgnore]d here; upstream serializes them into the request body
       even though both are path parameters.
     - JSON string escaping differs and is intentionally left alone:
       System.Text.Json's default JavaScriptEncoder escapes "+", "&", "<",
       ">", "'" and non-ASCII characters as \uXXXX inside string values,
       where upstream's Newtonsoft.Json writes them literally. The output
       is valid JSON that the Notion API decodes identically, so parity
       with upstream's exact bytes is not pursued.
     - The file-upload multipart content type is parsed with
       MediaTypeHeaderValue.Parse rather than constructed, so a Notion
       content type that carries parameters (e.g. "text/plain;
       charset=utf-8") does not throw.
     - Upstream's hard-coded workspace ids and spent OAuth authorization
       codes in the integration tests were replaced with values read from
       environment variables, and the integration test classes were put in
       a single non-parallel xUnit collection.
     - The target framework was narrowed from netstandard2.0 to net10.0.
